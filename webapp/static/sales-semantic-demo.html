BEFORE — 每种视图一套专用实现

Channel × Product
  → get_channel_product()
  → dedicated endpoint /dashboard/channel-products
  → dedicated frontend rendering
SalesRep × Product
  → get_salesrep_product()
  → dedicated endpoint /dashboard/salesrep-products
  → dedicated frontend rendering
Product aggregation
  → get_product_aggregation()
  → dedicated endpoint /dashboard/products
Product → SKU drilldown
  → get_product_sku_drilldown()
  → dedicated endpoint /dashboard/products/{id}/skus

新增一种分析视图 = 新增 service function + endpoint + filter/sort 映射 + 专用前端渲染。

Future Dimensions — Category

用户未来非常关心 Category × BP Channel，但当前 SalesFact 没有 Category snapshot。 本 Demo 不会 用 “SalesFact JOIN 当前 MDM → Category” 的方式伪造历史归属。

DimensionStatus说明
Option A — 销售 Publish 时冻结 Category snapshot（历史可复现，需新增 snapshot 列与 Publish 契约）。
Option B — 历史销售永远按当前 MDM 重新分类（实现便宜，但历史报表会随 MDM 变更而漂移）。
Demo 不替用户决定；在决策前 Category 维度不进入正式 Semantic Query Engine。
